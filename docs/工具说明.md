# 工具说明：这两个脚本是干什么的

> 这份文件是**手写**的，不会被 `sync_from_feishu.sh` 覆盖。
> `docs/source.md` 和 `docs/软件定义网络-课程项目留痕.docx` 才是自动生成的。

## 一句话

飞书 → Markdown → Word，中间两段路各由一个脚本负责：`sync_from_feishu.sh` 负责**取**，`build_docx.py` 负责**转**。

```
飞书云文档（唯一事实源，rev 21 / 13400 字符）
   │
   │ ① sync_from_feishu.sh
   │    lark-cli docs +fetch --doc-format markdown
   ▼
docs/source.md（Markdown 快照）
   │
   │ ② build_docx.py（python-docx）
   │    解析标题 / 表格 / 代码块 / 列表 / 引用 / 加粗
   ▼
docs/软件定义网络-课程项目留痕.docx（15 页，提交与答辩用）
   │
   │ ③ git add / commit / push
   ▼
GitHub main
```

## ① `scripts/sync_from_feishu.sh` —— 取

**作用**：一条命令完成「登录态下抓飞书 → 写 `docs/source.md` → 调 `build_docx.py`」。

**为什么需要它**：

- 抓取要传文档 URL、指定 `--scope full --doc-format markdown`、还要把 JSON 里的 `data.document.content` 取出来写成文件；这三步每次手工做都会错一处。
- 中间文件用仓库根目录的 `.leftrace.json`，脚本退出时自动删除（Windows 下 MSYS 的 `/tmp` 与原生 Python 不互通，踩过坑）。
- 文档换了（比如以后拆成多个文档），只改脚本里的默认 URL 或传参，不用改流程。

**典型输出**：

```
[1/3] 从飞书抓取 Markdown ...
[2/3] 写入 docs/source.md ...
    13400 字符
[3/3] 生成 docx ...
OK: docs/软件定义网络-课程项目留痕.docx
```

## ② `scripts/build_docx.py` —— 转

**作用**：把 Markdown 渲染成能交的 Word 文档（约 290 行，只用 `python-docx`）。

**为什么不能用飞书自带导出**：当前应用只有 `docx:document*` 这几个 scope，**没有** `docs:document:export`，API 导不出 docx；而提交物必须是 Word。

**它具体做了哪些"脏活"**（都是实际踩出来的）：

| 问题 | 处理方式 |
|---|---|
| 飞书用 `###` 当小节（没有 `##`） | 标题层级归一化为「一级章节 + 二级小节」，Word 导航窗格才正常 |
| 表格分隔行是 `|-|-|` 单横线 | 单独识别并跳过，否则表头下面多一行 `-` |
| 长表格跨页 | 首行设 `tblHeader` 重复表头，所有行设 `cantSplit` 不拆断 |
| Word 自动编号跨列表连续计数（1–3 后面接 4–8） | 编号列表不使用自动编号，直接把 `1.` 写进文本 |
| Mermaid 图在 Word 里没渲染器 | 保留源码，前面加一行小字注明「飞书版为画板」 |
| 行内 `**加粗**`、`` `代码` ``、`[链接](url)` | 拆成独立 run，分别加粗 / 等宽字体 / 追 URL |

**为什么必须是脚本，而不是手工排版**：文档 15 页、16 张表格、十几个代码块，手工改一次就和飞书版本漂移；脚本保证「飞书一改，Word 跟着变，且每次结果一致」。

## 为什么这两个文件要传到 GitHub

1. **可复现**：`.docx` 是二进制，别人无法 review、无法 diff、冲突无法合并。脚本是它的"源代码"，有脚本才谈得上复现。
2. **过程留痕**：课程要求过程可追溯。仓库里能看出"这份 Word 是怎么从飞书变出来的"，而不是凭空出现一个文件。
3. **四人协作**：A/B/C/D 都要用同一份文档，谁都能 clone 后跑一条命令重建；规矩是**只允许脚本生成 docx**，不允许两人各改一版再合并。
4. **答辩可验证**：老师 clone 下来，`bash scripts/sync_from_feishu.sh` 就能重跑一遍，证明链路是真的。

## 两个不要

- 不要手改 `docs/source.md` 和 `.docx` —— 下次同步会被覆盖。
- 不要把 `.docx` 当成"唯一真相" —— 真相在飞书；仓库里的是快照 + 生成器。
